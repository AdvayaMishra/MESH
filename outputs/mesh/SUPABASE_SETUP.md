# Supabase setup

1. Provision a project in your own account. Enable asymmetric JWT signing with ES256 or RS256, verified email, CAPTCHA, strong password policy and refresh rotation/reuse protection. Configure short numeric signup OTP email templates, expiration, resend cooldown and provider rate limits. Confirm provider plan limits.
2. Set SUPABASE_URL and SUPABASE_ANON_KEY through environment configuration. Identity operations do not require a service-role key. Optional private Storage uses a separate protected SUPABASE_STORAGE_KEY backend credential; never provide that key to a frontend.
3. Keep authentication passwords in Supabase Auth. Application memberships store only subject UUID, normalized email, organization role and active status.
4. To use hosted PostgreSQL, use separate migration-owner and restricted runtime roles on an approved direct/pooler connection. Require verified TLS in your connection string. Run `alembic upgrade head` as the migration administrator, then `scripts/bootstrap_role.py` with MESH_DB_PASSWORD. Check role grants, RLS and policy behavior before use. Do not run application requests as postgres/service role.
5. Do not grant application domain tables to `anon` or `authenticated`. All business access goes through this API. PostgreSQL RLS uses backend-set transaction context, not browser-provided JWT database claims.
6. Apply `supabase/storage/0001_private_identity.sql` and `supabase/policies/0001_revoke_direct_clients.sql`. Configure private Storage and ClamAV before trying uploads. Backend upload, HR-only signing, human decisions and retention are implemented for PNG/JPEG. Private isolated image OCR is implemented with encrypted suggestions and manual fallback; it remains disabled for real processing pending production configuration and review. PDF processing and legal-hold support remain pending. Bounded orphan reconciliation is implemented; actual synthetic private Storage upload/download/signing/client-denial and OCR download checks have passed. Do not collect real identity documents before live authorization, retention and privacy validation.
